# Sales Demo

Use this script when showing VibeBoard as a product. Keep the story focused on
hardware execution and verification, not browser-side AI code generation.

## One Sentence

VibeBoard lets local coding agents modify embedded projects while the web app
compiles, flashes, renders, observes, and proves what actually ran on hardware.

## Demo Flow

1. Show board selection across ESP32-S3, Huangshan Pi, and Nordic.
2. Explain that source changes happen in local Codex, Claude Code, or a normal
   IDE through MCP and repository files.
3. Run ESP32-S3 compile and show Build Evidence.
4. Run an ESP delivery path and show Device Evidence.
5. Switch to Huangshan Pi, show Bridge readiness, compile, flash, and readback.
6. Export the evidence report and point out file hashes plus flash hash match.

## Claims To Make

- The web product is a hardware execution console.
- Local agents remain in their strongest environment: the user's repository.
- The page owns expensive hardware operations: compile, flash, render, monitor,
  readback, and report.
- Evidence reports make demos, classrooms, support, and paid templates easier
  to trust.

## Claims To Avoid

- Do not say the browser is the main AI coding surface.
- Do not imply Nordic has the same real hardware proof as ESP32-S3 or Huangshan
  until the local DFU/verification path is finished.
- Do not claim a sensor is real unless the truth report marks it real or
  verified.
